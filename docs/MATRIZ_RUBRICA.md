# Matriz de cumplimiento de la consigna final

Fuente: `Proyecto_Final.pdf`, UES, 2026. La prueba se considera *pendiente* hasta que se ejecute y evidencie.

| Criterio | Evidencia que necesitamos | Estado inicial |
|---|---|---|
| Plan de pruebas | Pruebas por módulo, conexión DB, entradas/salidas, defectos y capturas | Parcial: scripts backend y BD |
| Métodos de conversión | Comparar directa, paralela, piloto y por etapas; justificar elección | Pendiente de informe final |
| Planificación de conversión | Actividades, responsables, duraciones, dependencias, riesgos y contingencia | Pendiente de informe final |
| IA | Caso de uso concreto o propuesta fundamentada; herramientas utilizadas, beneficios y límites | Propuesta pendiente |
| Conclusiones | Resultados medidos, limitaciones y alcance real | Pendiente |
| Bibliografía | Referencias verificadas en APA 7 | Pendiente |
| Presentación del PDF | Plantilla institucional, orden, figuras y tablas legibles | Pendiente |
| Inicio del sistema | URL pública + respaldo local; login sin fallos | API parcial, falta frontend |
| Módulos principales | UI de personal y turnos vinculados a API | Pendiente |
| BD CRUD | Conexión, alta, consulta, modificación y eliminación controlada | Parcial |
| UX/UI | Navegación, validación en formularios, estados vacíos y errores | Pendiente |
| Seguridad | JWT, RBAC y ámbito departamental desde UI | API parcial |
| Pruebas y errores | Evidencias de defectos, correcciones y resultados | Parcial |
| Dominio técnico | Arquitectura, decisiones, API, SQL, pruebas | Preparación pendiente |
| Participación y defensa | Todos explican y responden preguntas, con cámara según consigna | Ensayo pendiente |
